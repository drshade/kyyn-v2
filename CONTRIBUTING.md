# Contributing to Kyyn

Read [the SDLC](docs/SDLC.md) and [project practices](docs/PROJECT-PRACTICES.md).
The [worked examples](docs/examples/README.md) illustrate proportional use of
Issues, ADRs and PRs; they are not mandatory numbers of artifacts or steps.

For product design, start with [architecture/](architecture/README.md). ADR file
conventions live in [architecture/adr/README.md](architecture/adr/README.md).

Before requesting review, choose proportionate checks from
[project practices](docs/PROJECT-PRACTICES.md#verification) and record their results
on the PR. The scripts own suite membership; test headers describe coverage.

Use the Issue and PR templates. The PR records verification and review evidence;
its author does not infer merge authority from a passing check.
