# Kyyn architecture review

**How to read this.** I read the whole set myself, then six independent reviewers re-traced the journeys with distinct lenses and returned 65 findings. I merged those with my 23. The planned adversarial verification pass was cut when you asked to wrap up, so corroboration below means "raised independently by N reviewers", not "verified by refutation". The acquisition-lens reviewer did not finish, so the evidence/plugin findings rest on my reading plus Astra's confirmation. Astra answered six intent questions; I mark each as owner decision, Astra's proposal, or agreed gap.

## High priority

**1. `Program SnapshotRead` on queries and renderers has no use.** `0017-outputs.md` Query/Output types, `0009-capabilities.md` ReadPage, `0008-authoring.md` monthlySummary. Every query, validator, renderer and evolution entry receives the whole guest `Root` as a value, `0006` commits to whole-root in-memory evaluation, and no example ever issues `ReadPage`; `SnapshotRef` is produced by nothing. Raised by 5 reviewers. Astra: his tightening, not an owner requirement; agrees pure is the better start. Correction: `Query (args -> root -> result)`, same for the renderer; delete SnapshotRead; keep `Program` for evolution entries and plugin methods, and prove the continuation there with a fake provider.

**2. Nothing owns how queries, outputs and methods get names, contracts and capability rows.** `0017` `SomeQuery` carries no name, so `KbDefinition` cannot yield `QueryDescriptor.name`; `0008`'s `Method` handle is "generated" from an unowned declaration; `SchemaMetadata` in `0005` has only roles and collections; no operation enumerates a root's descriptors. Raised by 4 reviewers. Astra: real gap. The schema experiment's `Frontend.hs:41` already enumerates exported values with resolved types. Correction: state in `0008` that SchemaInspection discovers named top-level declarations selected by an explicit export convention, taking name from the identifier, contracts from the resolved type and the capability row from the `Program` index; add `queries`/`outputs` to `InspectedSchema`; drop `KbDefinition` and the pre-generated handle.

**3. Fact identity is inside the payload in `0005` and outside it in `0006`, `0009` and `0010`.** `CollectionDecl.idField` vs `Fact { id, value }` and `CollectionBinding`. Two prototype conventions carried into two ADRs; `each transform` can silently rewrite an ID under one model and cannot touch it under the other. Correction: decide once in `0006`; delete either `idField` or `Fact a` and reference from the other ADR.

**4. `RootPublication`'s row cannot do what `AcceptEvolution` promises.** `0012` row is Git, FileSystem, Failure, yet it must read Ready state and compare live bytes with captured material for `NotReady`/`WorkspaceChanged`, dereference opaque `FactSnapshot`/`CodeSnapshot`/`WorkspaceSnapshot`, and write the Dhall report archive without DhallHandling. Raised by 4 reviewers. Astra: real gap; handles were deliberately not Git trees, favours explicit RootStore/EvolutionStore reads in the lowering, and the final ref check must stay in publication. Correction: move the two preconditions into the composing application operation, add read access to both stores in the publication row, or give the snapshots a stated representation in `0004`. The Git-tree-object option is worth weighing since both store rows already include Git.

**5. No operation saves or reloads a candidate, yet headless accept depends on one.** `0025` script accepts in a fresh process; `0012` requires "the checked result and unchanged captured inputs"; `EvolutionStore` in `0010` lists only List/Create/Capture. Raised by 3 reviewers. Correction: add `SaveCandidate`/`LoadCandidate` to `0010`, state that `applyEvolution` saves and `accept` reloads then re-runs `checkCandidate` without acquisition, and name the materialized snapshot location.

**6. Examples are workspace material, so they stop being checked after acceptance.** `saveExample` in `0023` takes a workspace; `0010` archives and excludes accepted workspaces from builds; `0012`'s overlay lists only facts, schema and code. Raised by 3 reviewers. Correction: state in `0010` that examples are root content in `CodeSnapshot`, a workspace proposes changes to that set, and `checkCandidate` runs the candidate root's examples. Related: `Example` embeds a whole-contract `ContractId`, so a role-only edit invalidates every saved example, contradicting `0011`'s "unchanged types" promise. Compare `shapeOf`, not the identity.

**7. The workspace layout that maps proposed root code onto the published root is undefined.** `0010` says the candidate's `CodeSnapshot` is "projected from context.material"; `0012` overlays "facts, schema and code" from it. Whether the workspace holds a full target copy, an overlay with tombstones, or something else is never stated, and the first slice is a code-only evolution. Correction: one paragraph in `0010` picking overlay or copy and naming which workspace files are evolution-only.

**8. `EvidenceRef` conflates a transient snapshot handle with a durable citation, and the evidence read path is undecided.** `0009` ReadEmail takes it as the read context; `0010` Rationale lists it as provenance; `0014` says citations must outlive the cache with producer and item identity. `0009` reads evidence through a plugin process per call; `0014`'s `readEvidencePage` reads stored typed pages. Astra: yes, blurred; neither route settled; do not mandate both. Correction: split into `EvidenceSnapshotRef` and `SourceCitation` in `0014`; store typed pages at acquisition and read them through a host capability with generated bindings so ordinary reads spawn no plugin; type the plugin's cache/checkpoint write capability, which is currently a table row with no signature.

**9. Wire codec default.** `0007` names a guest JSON library as the default although both pipe ends are Kyyn-generated, the profile already forbids JSON numbers and defaults, no library has compiled under MicroHs, and microaeson is GPL-3 under a proprietary policy. Raised by 2 reviewers. Astra: JSON was a proposal, not owner dogma; a generated grammar is legitimate but transfers framing, escaping and codec maintenance to Kyyn; wants a concrete cost comparison. Correction: change "No parser implementation is authorized" to "no partial-grammar parser", add an SDK-owned canonical codec as a first-class candidate in the protocol investigation, and bring the choice to you with costs rather than leaving the library as the implied default.

## Medium priority

- **Ready-to-Draft on edit is unobservable.** `0010` persists Draft/Ready/Accepted and says editing demotes Ready, but drafts are ordinary files with no watcher; `0012`'s computed `WorkspaceChanged` covers the same case. No operation sets Ready. Raised by 4 reviewers. Strike the sentence, add `SetEvolutionState` Draft↔Ready, and state that head's committed manifest is authoritative for Accepted so a stale working-tree copy cannot cause a confusing `BaseMismatch` after a kill mid-sync.
- **Evolutions take no runtime arguments while outputs take `--args`.** `0010` binds `September` in source, so the `0025` monthly script must invoke an LLM every run just to change a literal. Either allow `evolution :: args -> Before.Root -> Program ...` with a generated contract, or state the consequence explicitly in `0025`.
- **A human cannot change anything without an agent.** `0023` declines any Web route that generates an evolution; `0016` still promises Web config editing; design-notes/README.md earlier said UI edits lower to evolutions. Raised by 2 reviewers. Add an explicit exclusion or a small structural-edit journey to scope.md and reconcile `0016`.
- **Commit-OID base equality makes every draft-sharing commit invalidate the shared draft itself and all other open evolutions.** `0012`, `0013`. Raised by 2 reviewers. Astra: commit equality is an explicit owner decision; root-subtree equality was never weighed. Needs your direction: keep and say "always", or define accepted-root material and compare that tree while the branch CAS keeps an expected commit.
- **Candidate identity is forbidden in `0007`/`0012` but required by `0023` notes and by "unchanged captured inputs".** Name a content identity, exclude review notes from the capture comparison, and say where notes live.
- **Before-Mid-After composition cannot work as captured.** `CapturedEvolution` carries one `targetSource`; `0010` requires Mid to be inspected and bound. Raised by 2 reviewers. Add intermediate sources or drop the slice-3 requirement.
- **Identity and code-only evolutions have no home for their explanation.** `Rationale` is per step; `identityEvolution` has none; `CommitMetadata`'s message source is unnamed. Raised by 2 reviewers. Add `explanation` to the manifest.
- **`0011` promises transition checks that no validator signature can receive**; `checkCandidate` cannot even load Before. Delete the sentence or state that change rules live in `evolve` steps.
- **Step observations encode both sides of every boundary.** For n steps the guest ships 2n whole roots; the host already holds Before and receives After, so n suffice. Change `StepObservation` to carry the step's output only.
- **Two MicroHs compilers.** `0005` links frontend internals into the kernel; `0020` ships `mhs` separately; nothing says they are one build. Raised by 2 reviewers. State the single-revision invariant, report skew in readiness, and record running inspection through the bundled `mhs` as the alternative to linking internals. Related: the metadata export's transport is unowned and drags RootStore onto the `0007` gate.
- **`PrepareOutput` needs the sink's input contract but `RootExecution` excludes PluginInvocation**, which is where `0015` puts descriptor discovery. State that the contract comes from SchemaInspection over vendored plugin source.
- **`prepareOutput` demands `Validated Root`, so the "report differences" review dimension in `0023` is unavailable for a rejected candidate.** Extend `0011`'s relaxation to candidate rendering.
- **`ListEvolutions` transitively installs SchemaInspection** via `runEvolutionStore` → `RootStore`, contradicting "installs no compiler" in `0003`/`0018`. Reword to "invokes none" or split listing from creation.
- **Dhall fact storage adds a second structural projection and a third codec for one algebra**, with no rationale recorded in `0006`. Raised by 2 reviewers. Owner-selected, so: record the reason, keep Dhall for human-edited config, and consider the wire profile for machine-written facts so the guest could load a snapshot from disk with its own generated decoder.
- **Roles as string metadata.** `RoleDecl`/`FieldRole` is a two-level indirection from kyyn-v1 with no journey, and `references` address only top-level fields while BEE needs nested references. SDK newtype wrappers recognised by resolved identity, the mechanism `0005` already mandates for `Fixed`, would be compiler-checked. Owner-selected as "Haskell metadata", which wrappers still are; record and pick.
- **Delivery records have no location, scope or enumeration**, and `0006` lists only disposable caches. Raised by 2 reviewers. Name the per-KB location, pass a `DirectoryScope` like `runSecretStoreIO`, and say it is not a cache.
- **Source root is re-validated on every preview**, a rule decided in boundaries.md rather than an ADR, doubling the flagged whole-root cost. Raised by 2 reviewers. Own it in `0011` and make it optional input.
- **Slice 3 in `0021` bundles eight proofs** and cannot be reviewed as one boundary. Split into CLI engine, MCP handoff, Web review, all before slice 4.
- **`Functor Candidate`.** Every documented use is warned against; mapping breaks the report-equals-value invariant `0010` enforces. Raised by 4 reviewers. Astra: you explicitly liked the convention. I still recommend removing it, but it is your call.

## Low priority

- No ADR owns KB creation; `CreateEvolution` needs a revision, so genesis is template copy plus ordinary Git commit, never stated. Raised by 3 reviewers.
- `ArtifactStore` has a loader, no creator and no journey; renderers are read-only and the wire forbids bytes. Raised by 3 reviewers. Remove until a binary output exists.
- Several KBs per repository and `NewSchema ProposedSchemaModules` appear without a journey.
- Working-tree sync omits deletions; a deleted fact's file survives in the worktree and `git add -A` resurrects it. The prototype had exactly this defect.
- Headless script addresses workspaces by `EvolutionName` while accepted ones are retained forever; the second `monthly-import` collides.
- File sink's guest write algebra is undefined; `recordHistory` needs fact-to-path routing RootStore does not expose.
- `0008` defers to "standard optics if compatible" while `0002` already rejects microlens.
- Under-claiming: the GADT request tree and higher-order process handler are already proven by the prototype; narrow the gates to the rank-N fold and `:+:` composition. Raised by 3 reviewers.
- Restated decisions: single evolution binding in 7 documents, no guest propose in 6 files, Ready-is-intent 4 times, rebase procedure in full twice, file-sink lowering in full twice. About one ADR line in five is a negation. Keep each in its owner and reference elsewhere.

## Decisions that need you

Three items Astra confirmed are owner decisions whose consequences were not weighed: commit-OID base equality versus accepted-root tree equality, `Functor Candidate`, and Dhall for facts. Two are open technical choices he agrees should come to you with costs: the guest wire codec, and where evidence is decoded. Everything else above is an agreed gap or Astra's own proposal, and the corrections are small document edits.
