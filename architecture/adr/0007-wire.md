# Library-backed JSON hidden behind typed adapters

## Context

Dhall storage follows the [sealed-tool/KB principle](../principles.md#seal-the-tool-and-the-kb-the-agent-reconciles-them).
Maintaining a guest-side partial Dhall parser
is not a product goal. JSON libraries can handle syntax while generated
bindings handle domain types. Neither JSON nor Aeson defaults are a lossless
Haskell data contract by themselves.

## Decision

Use UTF-8 JSON metadata and packed byte sections via a small request/response, private host/guest protocol.
Use maintained JSON libraries in the native host and GHC guest (Aeson in the
first backend), with exact dependencies pinned by their builds. Libraries handle
syntax; the restricted value profile below remains authoritative regardless of
library defaults. Preserve upstream notices under ADR 0022.

### Description before invocation

The same built guest executable supports these initial requests. They use the
framing below and a fixed protocol codec that does not depend on the KB's types:

```haskell
data GuestEntry
  = Describe DescriptionSelection
  | Invoke EntryId WireValue

-- Describe returns the structural contracts and
-- metadata, entry input/result/capability descriptors, and selected API exports.
-- Invoke names the entry and supplies its argument value.
```

The host decodes messages against the current protocol types and derives checked
contracts from the description (ADR 0005) before supplying facts or capability grants.
Describe admits no HostRequest: an attempted effect is a protocol failure.
Generated descriptors correspond exactly to the manifest registrations in the
selected build scope, including fixed SDK root/validation/evolution entries.
Unknown, missing or duplicate registered entries are rejected; exported library
helpers appear only in API discovery, not as unregistered invocable operations.
The build checks correspondence to the captured manifest, and the host verifies
entry names/kinds against that same selection.

Description and invocation use the same immutable build (ADR 0002); the host
never describes one executable and invokes a freshly resolved replacement.
Malformed description, unsupported shapes or wrong contract identities fail before
host-effect dispatch. This is structural validation of trusted guest interfaces,
not attestation of arbitrary native code. No compatibility negotiation is added.

Kyyn generates mappings between library JSON values and constructors/fields of
the supported, compiler-inspected authored ADTs. Authors do not maintain codecs
or a second schema. Library parsing/printing and generated structural decoding
are separate responsibilities: the latter checks tags, fields and payload types.
Generated ADT mappings require real built-guest round-trip tests, not only JSON-value
parser tests.

SDK-generated adapters own serialization, framing, request IDs, method dispatch,
contract matching and structured failures. Ordinary KB/plugin code never sees
`Value`, JSON text, pipe handles or response envelopes. The native host translates
disk values into this representation; it does not send executable Dhall expressions.

The wire is structurally checked on the host; it cannot carry the guest's GADT
index or continuation. A representative pair of private envelopes is:

```haskell
data GuestMessage
  = HostRequest RequestId CapabilityId MethodId WireValue
  | Completed WireValue

data HostMessage
  = HostResponse RequestId (Either HostCallError WireValue)
```

`WireValue` belongs to the selected JSON library/profile, not the public SDK.
`HostCallError` is an encoded, declared request failure; a broken frame/channel is
a protocol failure and need not pretend to be a well-formed response. Handshake
and initial-entry messages are additional protocol cases, not expanded here.
Recoverable errors that authored code handles must be part of the request's
declared result, for example `Either PluginError output`. An envelope-level error
with no such declared mapping aborts the invocation through the adapter; it is
never cast into the continuation's expected `x` or converted into an empty page.

The adapter decodes a frame, resolves its method in the invocation's available
capabilities, checks the input against the descriptor, then dispatches. It checks
the output against the result contract before replying. The guest's generated
decoder then reconstructs the precise `x` required by the suspended request in
[Program](0009-capabilities.md). A response ID match alone is not a type check.

For clarity, the pure codec boundary can have this shape without selecting a
JSON library or exposing it to authors:

```haskell
data Frame = Frame { metadata :: Bytes, body :: Bytes }

decodeMessage :: Frame -> Either ProtocolDiagnostic GuestMessage
encodeMessage :: HostMessage -> Frame
```

`decodeMessage` consumes one complete frame after framing has handled chunked pipe
reads. It validates envelope syntax and the permitted body section, not capability availability or KB semantics.
Both functions use a library parser/encoder. Field/tag generation is our work;
reimplementing JSON parsing is not. The [contract checker](0005-contracts.md) is
the separate boundary that turns parsed structural inputs into `CheckedValue`.

Each frame contains exactly two sections: JSON metadata, then a raw body. The
body is empty except for HTTP requests (including blob-download requests), HTTP
responses of any status and successful blob-read responses. HTTP
metadata contains method/URL/headers or status/headers respectively, not an
escaped copy of the body. The typed HTTP boundary remains UTF-8 text under
ADR 0009; decoding it does not require parsing a JSON string containing JSON.
Only a transport failure has no raw body: non-2xx responses retain their bodies
for provider interpretation, including OAuth errors and Graph error details.
Blob downloads return metadata only; successful blob reads carry exact bytes
without text encoding. Failed blob reads have no raw body. Other messages reject
a nonempty body.

Each section consists of zero or more chunks followed by a zero-length chunk.
A chunk is a canonical ASCII decimal byte count, LF, then exactly that many
bytes. There is no delimiter after its payload. Emit chunks of at most 64 KiB;
receivers reject larger chunks, noncanonical counts, premature EOF and incomplete
messages. The zero terminator is `0\n`. Empty bodies therefore need only that
terminator. Chunk boundaries have no semantic meaning and may split a UTF-8 code
point; assemble the section's bytes before decoding. Chunk size is transport
framing, not a limit on total message size or a usage quota.

Read exact chunks with native block I/O (`ByteString.hGet` in the GHC backend).
Stdout is binary protocol only; stderr carries
diagnostics. The host owns native OS pipes. The adapter must obtain binary
standard handles in the built guest on Linux, macOS and WSL2. Reopening
`/dev/stdin` and `/dev/stdout` is an implementation requiring platform verification,
not a portability assumption: socket-backed descriptors cannot necessarily be
reopened. A supported platform must have a verified binary-handle implementation;
do not silently fall back to text-mode transport.

The guest retains text in `Data.Text.Text` and bytes in `ByteString`. SDK identities,
messages and textual payloads use `Text`; library-facing `String` conversion is
local to adapters that require it, not a retained payload representation.
Encode and write results in bounded pieces rather than first constructing a
whole-result `String`. There is still one terminal `Completed` message, and no
per-page result protocol. Chunked framing avoids both a whole-result count pass
and requiring the entire encoded result to be resident before writing.

The throughput experiment in issue #199 motivates these choices: around 10 MB
of paged input took 35 seconds to read/parse/discard with line framing and 20
seconds with length-prefixed block reads. Retaining and returning that payload
took 100 seconds with strings and 32 seconds with packed retention, block reads
and bounded encoding; GC fell from 56% to 4.5%. At around 30 MB the combined
experiment completed in 85 seconds while the string-retaining control exceeded
six minutes. These are synthetic measurements, not performance guarantees.
Raw HTTP sections remove escaping and a decode pass; measure that change during
implementation rather than attributing an unmeasured speedup to it.

The plugin adapter begins with `{arguments, snapshot}` and emits
`{tag: "HostRequest", id, capability, method, arguments}` or a terminal
`{tag: "Completed", result}`. Its host reply is `{tag: "HostResponse", id, result}`:
`result` encodes the request's typed `Either FetchError a` directly, without a
second error wrapper. Request IDs are canonical integer strings. Wrong IDs, tags,
fields or payload types abort before resuming the continuation; source failures
decode as ordinary `Left` values. Config and payload codecs come from inspected
Haskell types. SDK evidence/change envelopes have fixed private codecs.
The native broker interprets only the request row selected for the entry, through
ADR 0009's host capabilities. Verification must exercise both direct acquisition
and composed captured-evidence calls across the installed boundary.

### Bounded acquisition batches

An acquisition's initial input additionally carries `concurrency`, a canonical
positive integer string chosen by native execution policy. The guest may not
increase it. ADR 0018 owns the default and operator override. Existing non-grouped
requests retain HostRequest/HostResponse; concurrent groups use a batch envelope
even when they contain only one blocked request. Other entry contexts reject batch
frames. This is one current protocol, not version negotiation or compatibility
with arbitrary older adapters.

The private batch cases have this structural shape (Bytes and WireValue are
host/runtime representations, not authored contracts):

```haskell
data RequestPart = RequestPart RequestId CapabilityId MethodId WireValue Integer
  -- Final field: bodyLength in bytes.
data ResponsePart = ResponsePart RequestId WireValue Integer

data GuestBatch = HostBatch [RequestPart]
data HostBatchReply = HostBatchResponse [ResponsePart]
```

Their envelopes have `tag` plus `requests` or `responses`. Each request member has
`id`, `capability`, `method`, `arguments`, `bodyLength`; each response member has
`id`, `result`, `bodyLength`. IDs share the invocation's increasing canonical integer
sequence with ordinary requests. Batch request IDs must be the next contiguous
sequence in metadata order. There must be 1 through `concurrency` members and no
nested batch envelope. Empty groups produce no frame.

The frame retains exactly two sections. Its raw body concatenates member bodies
in metadata order, partitioned by their canonical nonnegative integer bodyLength
strings. The lengths must sum to exactly the raw section's byte length, without
overflow or trailing bytes. Zero-length bodies remain explicit. Each member obeys
the existing method-specific body rules. The 64 KiB *chunk* bound remains unchanged;
there is no new total-body quota or base64 encoding.

Before dispatch, decode and validate the complete partition, all member envelopes,
ID sequence, contracts, supported methods, snapshot handles and concurrent-effect
allowlist from ADR 0009. A malformed or forbidden member rejects the whole batch
without dispatching its other members. Native workers return checked replies in
request order; one owner encodes the resulting frame after all workers complete.
No worker writes to the guest pipe. The guest verifies an exact ordered match of
response IDs, one result per pending request, the complete body partition and all
typed result decoders before resuming any continuation in that round. Unknown,
duplicate, missing or reordered IDs and invalid bodies are protocol failures.

One bounded round waits for its slowest member. A terminal Completed frame is valid
only when no requests or workers remain outstanding. There is no per-branch final
result publication and no automatic retry of a batch. Partial frames, a failed
response decoder or channel loss abort the invocation under ADR 0019.

## Value profile

Both peers use Aeson for JSON parsing and encoding. Non-ASCII text may be literal
UTF-8 or valid escaped UTF-16 surrogate pairs; lone surrogates and invalid UTF-8
are rejected. Validate Haskell String inputs before packing them into Text, which
would otherwise replace invalid surrogate characters. JSON numeric and null nodes
are outside this profile; numbers use strings and optionals use tags. Validate
the entire value before emitting the encoder's lazy byte chunks through bounded
framing. These are decoded-value checks, not another syntax scanner.

| Contract value | Wire representation |
| --- | --- |
| Record/list/text/bool | Object/array/string/boolean |
| Integer, Natural, exact Decimal | Canonical decimal strings, parsed by typed bindings; never via `Double` |
| Nullary union case | `{"tag":"Case"}` |
| Payload union case | `{"tag":"Case","value":…}` |
| Optional | Explicit `None`/`Some` tagged cases, preserving nested optionals |
| Stable identity, date, instant | Documented strings, checked by corresponding SDK type |
| Binary/large document | Typed artifact reference, not arbitrary embedded bytes |

No function values, type expressions, imports, NaN/infinity, omitted-field
defaults or implicit union guessing. Arbitrary domain numbers do not use JSON
numbers in this profile. Exact decimal syntax and rounding policy are separate:
the shared arithmetic library owns operations; the KB chooses business rounding.
The scalar rows refer to selected existing library types recognized under ADR
0005, not any KB record whose name happens to be `Decimal` or `Date`. Inspect and
preserve relevant parameters such as fixed resolution, and prove the generated
library-type/string codec in both peers. Structural records do not become decimal
scalars by naming convention. Prefer a maintained numeric implementation over
inventing arithmetic to fit the wire table. Unsupported library/codec mappings
must be rejected, never silently represented as `Double`.

Arbitrary authored newtypes follow the ordinary constructor mapping: a positional
wrapper is tagged, and a named record wrapper is an object. Transparency is not
inferred from a type's name or from being a newtype. The string representation
for identities/dates applies only to recognized SDK/library scalar types with
their selected codecs, not a KB-authored type merely called `FactId` or `Date`.

Generated frames have unique field names. Both peers reject messages containing
duplicate object keys at any depth, including equivalent escaped key spellings.
Reject duplicate fields in authored association lists before constructing an
object, so construction cannot silently discard a field. No semantic hashing of
arbitrary JSON source. JSON encoding must not introduce an extra candidate
identity or approval protocol; acceptance uses the Git base under ADR 0012.

## Protocol boundary and tradeoffs

The installed host owns its host-side adapter. The guest build generates
guest-side adapters under the KB's locked SDK pin. Invocation supplies a typed
entry input. Guest messages are host-capability requests or terminal results; the host
answers each request once. One outstanding frame exchange per guest, including
the bounded acquisition batch below. A parent
KB can synchronously call a plugin in another invocation; no recursive plugin
call graph in the first profile. Unknown methods and
unexpected message order fail before any requested effect is dispatched.

The outer invocation owns any nested plugin invocation and its resources.
Cancellation of the outer operation cancels outstanding child work and releases
its pipes/processes; no orphan guest waits forever for a response. Recoverable
plugin errors return as typed results to the suspended caller; fatal protocol or
process failures remain distinguishable. Per-call processes suffice initially;
pooling or reuse is not a prerequisite. Contract-compatible plugin result types
may be reused through generated bindings; re-project them only when domain
meaning requires it, not to cross the transport boundary.

Protocol changes update host and generated adapters together; rebuild guest artifacts
when the toolchain changes. A changed installed contract yields a clear repair instruction.
Process failure/cancellation follows ADR 0019, especially after external writes.

## Verification

Runtime integration tests cover raw Unicode and
controls, exact numeric strings and nested optionals, valid surrogate-pair acceptance,
lone-surrogate and invalid UTF-8 rejection, JSON-number/null rejection, truncated
input, trailing garbage and duplicate-key rejection. Check raw String values and
keys before Text construction; parsed Text values and keys already contain only
Unicode scalar values.
Invalid output values must be refused before any frame bytes are emitted. Exercise actual generated
ADT encoders/decoders in both directions, including unknown tags, missing fields
and wrong payload types; exchanging tagged JSON objects alone is insufficient.

Independent host/guest round trips: payload unions, `Some None`, empty values,
very large integers, exact decimals, Unicode/control characters, malformed and
truncated frames, duplicate keys, wrong methods and mismatched schemas. Include
actual runtime fact loading and a suspended multi-request program. The codec
and effect-encoding gates must not wait until the first external connector:
ADR 0021's reporting slice includes a typed KB tool with several host requests.
Exercise nested-call errors and cancellation as well as successful resumption.
No parser implementation is authorized by this ADR; generated field/tag mapping is the
limited codec work Kyyn consciously owns.

Verify that non-2xx HTTP responses preserve their raw bodies, while transport
failures have none. Include fragmented chunk headers/payloads, multibyte characters
split across chunks, empty sections and terminal-frame cancellation. A partially
written frame never dispatches a host call or publishes a result.
